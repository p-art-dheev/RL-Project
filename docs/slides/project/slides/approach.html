Our contribution

PACE: four changes, each aimed at one gap

N1 · Online, task-level

A policy scores every candidate node with one shared network, so it works for 5 or 500 nodes and simply masks dead or forbidden ones

N2 · One policy, any trade-off

The SLA weight w is an input, so one trained network covers the whole curve; a PI controller moves w to hold an operator's SLA target

N3 · Robust by design

Trained on noisy runtime estimates, failures, stragglers and bursts; batch work can wait for greener hours; a w-dependent safety shield

N4 · Same code, real machines

The scheduler that runs in the simulator drives real workers on AWS Mumbai, AWS Stockholm and the laptop edge

Honest positioning: each ingredient has precedents. GNN/DAG RL scheduling: Decima (SIGCOMM 2019). Preference-conditioned multi-objective RL: Abels et al. 2019. PID-Lagrangian constrained RL: Stooke et al. 2020. Carbon-aware temporal shifting: Wiesner et al. 2021. Shielding: Alshiekh et al. 2018. The contribution is the combination for carbon + SLA edge–cloud DAG scheduling, measured against the base paper, plus a real-system check.
